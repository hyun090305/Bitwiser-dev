# 16. 한 줄로 전송하기

**선택한 판:** `C5-06` · 원본 명세 유지.

| 구분 | 포트 | 의미 |
| --- | --- | --- |
| 입력 | `D0,D1,D2,D3` | 병렬 입력 |
| 입력 | `START` | 전송 시작 |
| 입력 | `RESET` | 전송 취소·초기화 |
| 출력 | `SERIAL` | 직렬 출력, 유휴 시 마지막 값 유지 |
| 출력 | `VALID` | 이번 출력 비트가 유효 |
| 출력 | `BUSY` | 아직 출력할 비트가 남음 |

**초기 상태:** 전송 중인 작업이 없으며 SERIAL=VALID=BUSY=0.

**동작 규칙**

- RESET=1이면 전송을 취소하고 SERIAL=VALID=BUSY=0으로 만든다. START보다 RESET이 우선한다.
- tick 시작 시 전송 중이 아니고 START=1이면 D3D2D1D0을 받아 고정하고, 그 tick에 D3을 출력한다.
- 이후 세 tick에 D2,D1,D0을 순서대로 출력한다. 전송 도중 병렬 입력 D가 바뀌어도 이미 받은 단어는 바뀌지 않는다.
- 네 비트의 출력 tick에서 VALID는 모두 1이다.
- BUSY는 이번 tick을 처리한 뒤 아직 출력할 비트가 남아 있으면 1이다. 따라서 마지막 D0 출력 tick에는 VALID=1, BUSY=0이다.
- tick 시작 시 전송 중이었다면 START를 무시한다. 마지막 D0 출력 tick에 들어온 START도 무시한다.
- 새 전송은 마지막 비트를 출력한 다음 tick부터 시작할 수 있다.
- 전송도 새 START도 없는 tick에는 SERIAL을 유지하고 VALID=BUSY=0으로 한다.

시작 tick을 t라고 할 때, RESET 없이 한 단어를 전송하는 일정은 다음과 같다.

| tick | SERIAL | VALID | BUSY | 새 START 처리 |
|---|---|---:|---:|---|
| t | 시작할 때 받은 D3 | 1 | 1 | 이 tick의 START로 시작 |
| t+1 | 시작할 때 받은 D2 | 1 | 1 | 무시 |
| t+2 | 시작할 때 받은 D1 | 1 | 1 | 무시 |
| t+3 | 시작할 때 받은 D0 | 1 | 0 | 무시 |
| t+4 | 새 전송이 없으면 마지막 D0 유지 | 새 START 여부에 따라 0/1 | 새 START 여부에 따라 0/1 | 새 전송 가능 |
