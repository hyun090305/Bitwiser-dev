# 14. 응답 확인 / Response Check

[Issue #475](https://github.com/hyun090305/Bitwiser-dev/issues/475)에 따라 ID 29의 준비/공개 문제를 교체합니다. 슬롯 `C5-04`, 노드 `staging_register`, Memory Link 소속과 자유 IO 배치는 유지합니다. 사용자 후속 요청에 따라 격자는 기준 회로 주위에 최소 한 칸 여유를 둔 12×12로 축소합니다.

| 구분 | 포트 | 의미 |
| --- | --- | --- |
| Button 입력 | `A`, `B` | 각 경로의 응답 |
| 출력 | `GO` | 이번 tick에 두 응답을 모두 확인함 |

처음에는 응답 기록이 없고 GO=0입니다. 먼저 받은 응답은 시간제한 없이 기억하며 같은 경로의 중복 응답은 쌓지 않습니다. 이번 tick의 입력까지 포함하여 두 응답이 모이면 GO=1을 출력하고 두 기록을 모두 소모합니다. 확인 tick의 중복 응답도 남지 않습니다. 두 응답이 모이지 않은 tick에는 GO=0입니다.

동시 응답도 즉시 확인하며 다음 tick부터 새 응답을 받을 수 있습니다. `AB, AB, -`의 출력은 `1, 1, 0`입니다. RESET, 타임아웃, 쿨다운, 응답 순서 제한은 없습니다. 완료 tick의 결과와 tick 사이의 출력도 관측합니다.

[Issue #477](https://github.com/hyun090305/Bitwiser-dev/issues/477)은 초기 화면, 모든 입력 변경 뒤, 버튼 해제를 포함한 완료 tick 출력을 검사합니다. GO는 입력 변경과 버튼 해제만으로 사라지지 않습니다. 정답 상태는 pending=[0,0]인 초기 GO=0과 확인 직후 GO=1을 구별합니다. 해제는 추가 tick이 아니며 응답 기록을 다시 처리하지 않습니다. GO는 다음 실제 tick에서 기존 규칙에 따라 바뀝니다.

기준 회로는 두 응답 기록과 GO를 저장하는 D 3개를 사용하지만 내부 상태 표현이나 부품 수를 강제하지 않습니다. D의 EN은 계속 사용할 수 있습니다. 별 비용 기준은 null을 유지합니다.

현재 reference는 `memory20:response-check`, revision은 `response-check-2026-09-24`입니다. 이전 `staging-register`(1비트)와 `memory20:C5-04`(2비트)의 reference는 보존합니다. 이전 보드 정의는 `levelLegacyDefinitions[29]`와 `levelPreviousLayouts[29]`에서 검증하며, 체험판의 `legacyStageRecords` 및 정식판의 이전 비용 기록으로 설계·역사적 별·진행을 보존합니다.

12×12로 조정하기 전 PR의 14×17 응답 확인 회로도 이전 보드 정의로 보존합니다.
