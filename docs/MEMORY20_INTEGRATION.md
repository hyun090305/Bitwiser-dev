# 메모리 20문제 최종 적용

2026-09-18. 사용자 ZIP의 명세를 구현 자료로 읽고 기존 저장소에 적용했습니다. 원본 자료는 [handoff-20](handoff-20/README.md)에 보관했습니다.

후속 요청으로 20개 모두 입출력 고정을 해제하고, 기준 회로를 재배치하여 격자를 축소했습니다. 최소 6×6과 해답 주변 여유를 유지하며, 한영 설명을 플레이어용으로 다시 정리했습니다. 최신 크기와 처리 방식은 [자유 입출력·격자 축소 내역](MEMORY20_COMPACT_LAYOUTS.md)에 있습니다.

20개 논리 슬롯을 기존 숫자 ID에 대응시켰습니다. 기존 챕터·노드 ID·좌표·선행 조건을 유지하며, 검증 대기였던 13개를 공개하여 전체 플레이 가능 문제는 47개, 후보는 Overflow Detector 하나입니다. 체험판은 기존 17개입니다. 조합 곱셈기 ID 17과 메모리 개편 밖 문제의 정의는 유지했습니다.

## 실행과 채점

- 엔진의 기존 순서인 입력 적용 → 이전 Q로 D/EN 계산 → 동시 갱신 → 같은 입력으로 출력 재계산을 사용합니다. 다른 문제의 관측 시점을 전역 변경하지 않았습니다.
- 최종판 1~19번은 독립적인 행동 FSM을 사용하여 모든 도달 가능한 사용자/정답 상태 쌍에서 모든 입력을 검사합니다. VALID가 0이어도 DATA_OUT/SERIAL 유지 조건을 검사합니다.
- [Issue #477](https://github.com/hyun090305/Bitwiser-dev/issues/477)의 채점 버전 5는 31·35·36·44를 포함한 일반 memory20 19개의 초기/모든 입력 변경/완료 tick 출력을 검사합니다. 한 tick에는 D 동시 갱신과 버튼 자동 해제·settle을 포함하며 숨은 중간 출력은 검사하지 않습니다. 펄스와 승인 출력은 다음 실제 tick까지 유지합니다. 33은 현재 칸과 LEVEL를 비교하고, 38은 WRITE=0/1 모두에서 현재 ADDR의 기존 저장값을 읽습니다. 순수 관측과 상태 전이를 분리하며 [채점 event trace](grading-event-trace.md)의 순서로 재생합니다. 26·Lab/legacy·보존된 memory20:C5-04·나눗셈기의 계약은 유지합니다.
- 나눗셈기는 A=0..7, B=1..3의 24가지 고정 입력을 각각 0 메모리에서 검사합니다. tick 0을 제외하고 1~10 tick의 첫 COMPLETE만 판단합니다. 완료 전 Q/R, 완료 후 유지, 내부 알고리즘과 D 개수는 강제하지 않습니다. 틀린 첫 완료와 기한 초과는 별도 실패 사유 및 재생 가능한 trace를 제공합니다.
- 최종판은 AND/OR 두 입력, NOT 한 입력을 검사합니다. 공통 AND/OR 입력 상한은 조합 문제와 Lab을 포함해 2개이며, 미연결·단일 입력의 기존 평가값은 보존합니다. D+EN은 기존 D의 D/EN 연결 역할로 표현합니다.

## 실제 보드 회로와 비용

`tests/fixtures/memory20/{ID}.json`에 20개 게임 형식 기준 회로가 있습니다. 입출력 이름·D/EN 핀·직각 단위 경로·도선 비중첩·동시 갱신을 검사했습니다. 모든 입출력은 자유 배치입니다. 원본 정수 좌표를 그대로 게임 좌표로 취급하지 않고, 분기 트리와 실제 격자 배선을 생성했습니다. 분기점은 기존 JUNCTION만 사용하며 새로운 논리 부품이나 교차 블록을 추가하지 않았습니다.

원본의 4~45블록은 INPUT/OUTPUT 포함 논리 부품 수입니다. 실제 게임은 기존 `cost-v1`의 도선 점유·분기·D 가격을 별도로 유지합니다. [기계 판독 보고서](memory20-integration.json)에 논리 부품 수, 배치 블록 수, 격자 크기, 실제 게임 비용을 구분했습니다. 원본 블록 수를 강제 제한이나 증명된 최솟값으로 쓰지 않으며, 기존 미지정 별 임계값을 임의로 만들지 않았습니다. 큰 후반 문제는 전체가 화면에 맞게 시작하고 확대/이동하며 편집할 수 있습니다. 큰 캔버스가 콘솔의 CSS grid 열을 늘려 메뉴를 밀어내던 문제도 수정했습니다.

## 저장 호환성

현재 채점 버전은 5입니다. 버전 3/4의 원본 설계·역사적 별·클리어·해금은 보존하고 새 기준으로 검증하지 않은 기록을 현재 best/랭킹으로 승격하지 않습니다. 변경 전 공개 문제의 보드 정의를 `levelLegacyDefinitions`로 보관합니다. 데모 백업에서 이전 포트/격자를 가진 회로는 이전 정의로 검증하여 `legacyStageRecords`에 보존합니다. 해당 문제의 기존 재도전 접근권과 역사적 별을 유지하고, 원본 회로를 새 문제의 정답으로 간주하거나 새 보드로 조용히 변환하지 않습니다. 백업 내보내기 및 재가져오기에서도 보존합니다.

정식판의 이전 비용 기록과 클리어 접근권도 보존합니다. 현재 채점/문제 규칙과 일치하지 않는 비용 기록은 새 랭킹 기록으로 사용하지 않습니다. 온라인 저장 회로를 현재 문제에 불러올 때 격자/포트가 다르면 명시적으로 안내하고 원본 저장 파일은 그대로 둡니다. 원본은 Lab에서 확인할 수 있습니다. 실제 사용자 계정에 저장하거나 배포하지 않았습니다.

## 재생성과 검증

```powershell
npm run stages:memory20
npm test
npm run build:demo
npm run test:memory20:browser
npm run test:full:web
python -X utf8 docs/handoff-20/verify.py
node docs/handoff-20/verify_js.cjs
```

일반 재생성은 체크인된 실제 회로를 검증하고 한국어·영어 데이터와 맵을 생성하므로 별도 Python 라이브러리가 필요 없습니다. `scripts/route-memory20.mjs`도 기본적으로 검증된 배치를 재사용합니다. 배치를 새로 탐색하는 개발 작업에만 `prepare-memory20-layout.py`(NetworkX 3.6.1)와 `route-memory20.mjs --reroute C4-01` 등을 사용합니다. 배치 탐색은 최소 면적이나 최단 도선을 보증하지 않습니다.

검증 결과: 원본 Python/JavaScript 검증 20/20, 게임 엔진과 독립 Python 결과 5,782개 전이 일치, 24개 나눗셈 통과, 1~10 tick 완료 허용·11 tick 거절·잘못된 첫 완료·미완료·조합 해답 허용·취소 및 탐색 한도 확인. 단위/회귀 테스트 83개가 통과했습니다.

Edge 브라우저에서 실제 정식판 UI로 20개 기준 회로를 모두 통과시켰으며, 캔버스 화면 맞춤·잘못된 첫 완료의 반례·모바일 설명을 확인했습니다. 메모리 튜토리얼, 저장/백업/복원, 체험판 16개 채점과 Priority 진입, 한영 전환과 체험판 분리 검증도 통과했습니다. 정식판 브라우저와 Electron 시작 검사에서 47개 문제 및 기존 계정/Lab 진입을 확인했습니다. Electron 검사에는 기존 Google 프록시 오류 두 건이 기록되므로 온라인 인증까지 검증한 결과로 해석하지 않습니다.

실제 UI 결과와 스크린샷은 `test-results/memory20-*`에 기록합니다. 실제 기기, Safari/Firefox, 온라인 업로드 및 설치 패키지는 이번 검증 범위에 포함하지 않습니다.
