# 비용·별·성과 화면 개편

## 설정 위치

공통 가격은 `src/modules/circuitCost.js`의 `COST_RULES.prices`입니다.

| 부품 | 가격 |
| --- | ---: |
| WIRE: 중복을 제외한 실제 중간 점유 칸 | 1 |
| JUNCTION: 화면 이름 JUNC | 1 |
| NOT / AND / OR | 각각 10 |
| D: EN 사용 여부 무관 | 20 |
| INPUT / OUTPUT | 0 |

현재 게임의 `BLOCK_TYPES` 전체를 명시적으로 처리합니다. 알 수 없는 종류는 오류로 처리하며 무료로 간주하지 않습니다. 고정·불필요한 논리 블록도 집계합니다. 도선 경로의 블록 끝점은 제외하고 중간 칸을 중복 없이 셉니다. 블록이 있는 칸은 일반 도선으로 다시 청구하지 않습니다. 편집 이벤트가 확정됐을 때만 보드를 갱신하며 신호·속도·tick은 가격 입력에 포함하지 않습니다.

채점 버전 6의 [연결 규칙](connection-rules.md)은 가격/별 기준을 변경하지 않습니다. D 자기 연결도 중간 칸만 과금합니다. 이전 버전의 클리어·최고 별·설계·기록은 보존하지만 현재 비용/랭킹으로 인정하지 않으며, 현재 기록 생성·제출·조회에는 새 연결 검사를 적용합니다.

가격이나 점유 규칙을 변경할 때는 같은 파일의 `COST_RULES.version`도 올려야 합니다. 현재 버전은 `cost-v1`입니다.

별 컷라인은 **`levels.json`과 `levels_en.json`의 `levelStarThresholds`**에서 스테이지 ID별로 수정합니다. 두 언어의 같은 ID에는 같은 값을 넣으세요. Chapter 1·2의 16개 퍼즐에는 아래 기준을 적용하며, 나머지 30개 정식 퍼즐은 두 값 모두 `null`로 유지합니다. Tutorial ID 0에는 이 항목이 없습니다.

```json
"levelStarThresholds": {
  "1": {
    "twoStarMaxCost": 14,
    "threeStarMaxCost": 12
  }
}
```

2026-09-24 확정 기준입니다. Chapter 1은 원본 별 기준표를 유지하고, Chapter 2는 새 채점을 통과하는 회로의 비용을 바탕으로 조정했습니다. 숫자는 정상 통과한 회로의 비용 상한이며, 3별 조건을 먼저 적용합니다.

| 챕터 | ID | 문제 | 3별 상한 | 2별 상한 |
| --- | ---: | --- | ---: | ---: |
| 1 | 1 | NOT | 12 | 14 |
| 1 | 2 | OR | 13 | 15 |
| 1 | 3 | AND | 13 | 15 |
| 1 | 4 | NOR | 24 | 27 |
| 1 | 5 | NAND | 24 | 27 |
| 1 | 6 | XOR | 52 | 60 |
| 2 | 23 | Priority | 120 | 135 |
| 2 | 11 | 2-to-4 Decoder | 82 | 95 |
| 2 | 25 | 저장 스위치 | 24 | 28 |
| 2 | 7 | Majority | 54 | 65 |
| 2 | 27 | 2-to-1 Selector | 58 | 65 |
| 2 | 26 | 토글 조명 | 39 | 45 |
| 2 | 28 | 고장 기록등 | 38 | 58 |
| 2 | 29 | 응답 확인 | 95 | 120 |
| 2 | 30 | 자동문 | 92 | 105 |
| 2 | 31 | 변화 감지기 | 68 | 75 |

3별 비용은 2별 비용 이하여야 하며, 같은 값과 0도 유효합니다. 한쪽만 입력하거나 음수·소수·역전된 값을 넣으면 설정 검사에서 오류를 알리고 추가 별을 지급하지 않습니다. `npm run build:demo`로 체험판에도 반영합니다. 빌드 과정에서 기준 회로를 통해 컷라인을 만들지 않습니다. 이 컷라인 설정은 가격·채점·스테이지 규칙 버전을 변경하지 않습니다.

## 화면과 판정

- 기존 제작 옆 보드 안에 현재 비용, 검증된 개인 최고 비용, 별 목표가 표시됩니다. 팔레트 단가는 블록에 커서를 올렸을 때 툴팁으로 표시합니다. 보드와 결과 화면의 비용 명세는 제거했습니다. 기존 격자 치수와 조작 버튼은 유지합니다.
- 미설정 상태는 `기준 준비 중`입니다. 통과하면 이번 별은 1개이며, 다음 별까지 필요한 비용 감소 수치는 표시하지 않습니다. 비용 기록과 비용 랭킹은 계속 사용할 수 있습니다.
- 완료한 정식 스테이지의 맵 상태 문구 자리는 별 3칸으로 대체합니다. 맵과 결과 화면에서 동일한 별 도형을 사용하며, 획득한 별은 미세한 음영만 남긴 차분한 금색, 미획득 별은 어두운 슬롯입니다. 돌출 테두리와 발광 효과는 제거했습니다. 결과 화면에는 짧은 별 등장 효과가 있으며 동작 줄이기 설정을 따릅니다.
- 결과는 왼쪽 내 성과, 오른쪽 비용 랭킹입니다. 비용 동점·악화는 갱신으로 표시하지 않습니다. 이번 별과 과거 최고 별을 구분합니다. 랭킹 숨기기, 페이지 이동, 내 순위 행, 좁은 화면의 세로 배치를 지원합니다.
- 기존 최고 비용이 현재 문제·검증·가격 버전과 일치하면 새 컷라인으로 별을 다시 평가합니다. 새 설정을 적용하기 위해 재플레이할 필요가 없습니다. 역사상 최고 별은 줄이지 않습니다.
- Tutorial 결과에는 `튜토리얼 완료`만 표시하며 별·단계별 랭킹에 참여하지 않습니다. 맵의 중복 완료 문구와 체크 특수문자는 제거하고 완료 카드 스타일을 유지합니다. 튜토리얼 완료 플래그와 다음 단계 해금은 유지합니다. 정식 클리어 수 집계에서는 ID 0을 제외합니다. 챕터별 기존 연결·선행 조건은 변경하지 않았습니다.

## 저장과 연결

`src/modules/stageCircuit.js`에서 기존 체험판의 배치 검증을 공통화했습니다. `src/modules/costRecords.js`는 허용 부품, 격자, 고정 I/O, 도선 점유와 기존 정답 검증을 확인한 배치로 비용을 다시 계산합니다. 채점 시작 때 회로를 복사하므로 비동기 채점 중 편집된 다른 회로가 기록으로 저장되지 않습니다.

새 기록에는 총비용, 부품별 수량·단가·소계, 회로 스냅샷, 스테이지 ID, 문제 규칙 정의, 가격·채점·회로 버전이 함께 들어갑니다. 별 기준은 문제 규칙 식별자에 포함하지 않아 컷라인만 바뀌면 이전 검증 기록을 재사용합니다. FSM의 의미를 변경할 때는 기존 `GRADING_VERSION`도 올려야 합니다.

정식판 로컬 키는 `bitwiser:cost-progress:v1:<기존 닉네임>`입니다. 체험판은 기존 `bitwiser:web-demo:v1` 키와 백업 형식을 유지합니다. 과거 별·클리어·초안·해금 데이터를 유지하며, 가격 버전이 없는 과거 기록을 비용 0 또는 새 가격으로 일괄 변환하지 않습니다. 새 비용 기록으로 대체될 때 이전 버전 기록은 `previousCostRecords`에 보관합니다. 저장 실패는 세션 내 결과와 구분해 표시하고, 손상된 로컬 저장값은 복구용 키에 남깁니다.

기존 Firebase Realtime Database 연결을 사용하는 정식 퍼즐 비용 경로는 다음과 같습니다.

```
costRankings/<가격 버전>/<스테이지 ID>/<문제 규칙 SHA-256>/<기존 닉네임 SHA-256>
```

업로드는 회로를 다시 검증한 뒤 트랜잭션으로 개인 최저 비용을 유지합니다. 조회와 개인 기록 동기화에서도 저장된 회로로 비용을 다시 계산합니다. 같은 비용의 숨은 부품 수·힌트·시간 우열은 없습니다. 새 비용 랭킹은 공동 순위 방식(1, 1, 3)을 사용합니다. 첫 페이지 밖의 내 실제 순위는 목록 아래 별도 행에 표시합니다. 별 개수는 참가 조건이 아닙니다.

연결 없음, 로딩, 빈 목록, 미등록, 등록 중, 등록 완료, 조회 실패, 등록 실패를 구분합니다. 닉네임 확인과 네트워크 작업에는 시간 제한이 있으며, 온라인 응답을 기다리느라 내 결과·이동 버튼을 막지 않습니다. 다른 기기에서 저장된 현재 버전의 개인 회로 기록은 정식판 진행 로드 시 다시 검증하여 로컬 기록과 병합합니다.

기존 `rankings` 경로의 과거 기록과 전체 누적 랭킹은 별도로 보존됩니다. 그 숫자를 새 비용 순위로 해석하지 않습니다. **UGC의 기존 별도 랭킹·결과 정책은 유지**하며 정식 퍼즐 비용 랭킹과 섞지 않습니다. UGC/실험실의 지원 부품은 동일한 제작 비용 표시를 사용합니다. 새 복합 모듈 부품의 가격 정책은 정의하지 않았으며, 그런 종류가 들어오면 명시적인 가격 정책이 필요합니다. 체험판에서는 기존 정식판 안내만 제공하고 온라인 비용 서비스를 호출하지 않습니다.

실험실의 기존 비상 팔레트에는 `XOR` 항목이 있지만 현재 엔진 지원 목록에는 없습니다. 정상적인 스테이지 데이터에서 사용하는 팔레트에는 이 항목이 추가되지 않습니다. 이 비상 경로로 지원하지 않는 부품이 들어오면 단가는 `—`, 비용 보드는 정책 미지원으로 표시하며 무료로 계산하지 않습니다.

## 외부 서비스 상태

이 저장소에는 Steam SDK/자격 증명이나 서버 채점 구현이 없습니다. Steam 업로드를 성공한 것으로 표시하지 않습니다. Firebase도 기존 클라이언트 검증 구조이며, 서버가 비용을 인증한다고 주장하지 않습니다. 실제 배포에서는 새 `costRankings` 경로에 기존 공개·사용자 정책에 맞는 권한을 적용하고 운영 연결을 확인해야 합니다. 이번 작업은 운영 데이터 업로드나 권한 변경을 수행하지 않았습니다. 서버 검증을 추가한다면 동일한 공통 배치·채점·비용 함수를 사용할 수 있습니다.

트랜잭션 처리는 [Firebase 공식 읽기·쓰기 문서](https://firebase.google.com/docs/database/web/read-and-write#save_data_as_transactions)의 웹 호환 API를 따릅니다.
