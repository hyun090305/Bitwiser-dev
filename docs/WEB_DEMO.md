# Bitwiser 웹 체험판

## 실행

저장소 루트에서 다음 명령을 실행합니다. 기존 Electron 실행(`npm start`)과 패키징(`npm run dist`)은 유지됩니다.

```powershell
npm install
npm run build:demo
npm run preview:demo
```

체험판 주소: `http://127.0.0.1:8080`. `DEMO_PORT` 환경 변수로 포트를 변경할 수 있습니다.
체험판 소스를 수정한 후에는 `build:demo`를 다시 실행합니다. 출력 폴더는 `dist-web-demo`이며 독립된 정적 사이트로 사용할 수 있습니다. 이번 작업에서는 공개 배포하지 않았습니다.

`demo.html`은 빌드 템플릿입니다. 직접 파일로 열지 않고 빌드 결과를 HTTP로 실행합니다. 기존 `index.html`에서 실제 게임 영역·설정·힌트 마크업을 가져오기 때문에 편집기 HTML을 별도로 복제해 유지하지 않습니다. 기존 전체 웹 버전은 저장소 루트를 HTTP 서버로 제공하면 됩니다.

시작 화면은 정식판의 점으로 채워지는 Bitwiser 로고와 `START` 버튼을 재사용합니다. 신규·재방문 모두 같은 문구를 사용하고, 재방문 시 최근 초안을 엽니다. 체험판 전용 헤더와 하단 스테이지 목록은 없으며, 원래 캔버스 맵에서 스테이지를 선택합니다. 맵 HUD와 게임 내 시스템 메뉴도 정식판 마크업을 함께 사용합니다.

5개 챕터와 번호 없는 Auxiliary Systems를 둘러볼 수 있습니다. Chapter 1·2의 17개 문제를 포함하며, Chapter 3·4·5는 챕터 제목·소개만 제공합니다. 제외 문제 ID·이름·설명·정답·블록 데이터는 빌드 결과에서 제거합니다. Lab·사용자 문제와 후반 챕터는 정식판 안내창으로 연결됩니다. 배치와 공통 선행 조건은 [개편 현황](STAGE_RESTRUCTURE.md)에 정리했습니다.

정식판 안내창은 **랭킹 시스템, 전체 스테이지, 회로 샌드박스 제작 및 공유, 사용자 제작 문제 제작 및 공유**를 한국어·영어 카드 4개로 소개합니다. 랭킹 HUD/게임 메뉴, 제외 스테이지, 챕터 4의 샌드박스·사용자 문제 노드에서 같은 창을 열며 시도한 기능을 강조합니다. 모바일에서는 내용만 스크롤하고 닫기 버튼은 유지합니다. 정식판 기능이나 온라인 모듈을 실행하지 않습니다.

테마는 **미드나이트 네온**으로 고정하며 기존 정식판의 저장된 테마 선택은 변경하지 않습니다. 설정에서는 소리·언어·업데이트와 **진행 백업 저장/열기**를 제공합니다. 백업은 검증 후 사용자 버튼으로 복원하며 교체 전 현재 진행도 내려받습니다. 진행과 초안은 계속 자동 저장·복원합니다. 텍스트·GIF 결과 공유를 제공합니다.

기존 문제의 ID·격자·기본 블록·정답은 유지했습니다. XOR·NAND·Selector는 문제 이름이며 새로운 기본 블록이 아닙니다. NOR·NAND를 생략하고 XOR에 도달할 수 있습니다. 두 기본 분기를 합쳐 자동문을 완성한 뒤에도 모든 포함 문제를 다시 풀 수 있습니다. 복사·붙여넣기는 튜토리얼 완료 후 활성화됩니다. Priority는 기존 문제를 유지하되 검증되지 않은 별 2·3개 목표를 부여하지 않습니다.

정답 통과는 별 1개입니다. 별 2·3개는 표의 두 예산을 동시에 충족해야 합니다. INPUT·OUTPUT·JUNCTION을 포함해 모든 블록을 세며, 도선은 각 경로의 끝점을 제외한 점유 칸의 중복 제거 개수입니다. 수학적 최적값이라는 의미는 아닙니다. 힌트, 날짜, 풀이 시간으로 감점하지 않습니다.

`tests/fixtures/demo/{ID}-{2|3}.json`에 각 기준을 만족하는 실제 회로가 있습니다. Tutorial 회로는 `0-tutorial.json`입니다. 빌드 시 이 회로의 배선 기하와 진리표를 검증하고 자원 사용량에서 `demo-budgets.json`을 생성합니다. 별 기준은 수동으로 따로 관리하지 않습니다. 한국어·영어 진리표가 모두 검증됩니다.

개인 최고 기록은 블록 수 우선, 동률이면 도선 칸 수로 비교합니다. 최고 별 회로는 별도로 보존합니다. 최고 기록과 최신 초안은 독립적으로 저장되며 재방문 시 최신 초안을 자동 복원합니다.

## 저장·복원·공유

- 진행 키: `bitwiser:web-demo:v1`. 문서 형식 `version: 1`, `catalogVersion: 2`. 회로 스냅샷은 v3이며 기존 v2도 읽습니다. D/EN 역할과 INPUT 방식은 보존하고 Q·tick·일시적인 button 입력값은 저장하지 않습니다.
- 스테이지별 `draft`, `best`, `bestStars`를 보관합니다. 각 최고 기록에는 해당 기록을 낸 실제 회로와 그 회로의 별이 들어 있습니다. 별과 자원 수치는 복원 시 회로를 재채점해 계산합니다.
- 구조 변경을 400ms 동안 묶어 저장합니다. 스테이지 전환과 채점 전에도 반영합니다. 채점 테스트 입력은 원래 입력으로 복원하며, 애니메이션 값·GIF를 저장하지 않습니다.
- 클리어와 해금은 검증된 최고 기록 회로 및 공통 `stageCatalog.js`에서 계산합니다. 기존 클리어 문제는 새 선행 조건과 무관하게 재도전할 수 있습니다. 범위 밖 기록·힌트·최근 단계는 `archivedStages`, `archivedHints`, `archivedLastStageId`로 보존하되 체험판 진입에는 사용하지 않습니다.
- 언어·BGM·효과음·배경 애니메이션 설정은 기존 로컬 설정을 재사용합니다. 체험판 저장 문서의 테마는 미드나이트 네온이며, 정식판의 테마 설정 키는 덮어쓰지 않습니다. 기존 계정·토큰·Drive 기록·닉네임·클라우드 자동 저장 설정을 가져오거나 삭제하지 않습니다.
- 자동 복원과 파일 백업 모두 형식·버전·단계·좌표·중복 위치·고정 IO·입력 방식·배선·힌트·설정값을 검사하고 클리어 회로를 재채점합니다. 불완전한 편집 초안은 정답일 필요가 없습니다. 잘못된 백업은 현재 진행을 바꾸지 않습니다.
- 저장 차단·용량 부족은 화면에 알립니다. 메모리에서 플레이와 진행은 계속 사용할 수 있지만 새로고침 시 이번 진행이 사라질 수 있습니다. 손상된 기존 저장 문서를 바꾸기 전에는 `bitwiser:web-demo:v1:recovery`에 원본 보관을 시도하며, 그것도 실패하면 원본을 덮어쓰지 않습니다.
- 공유 화면에서 현재 회로를 재확인해 별과 자원 사용량을 표시합니다. 미통과 회로는 초안으로 표시합니다. 텍스트 복사·텍스트 파일 다운로드·GIF 다운로드와 지원 환경의 네이티브 텍스트 공유를 제공합니다. GIF에는 결과 캡션이 들어갑니다.

## 체험판 흐름과 서버 분리

시작 버튼은 바로 스테이지로 연결하고, 통과 후에는 결과창을 표시합니다. Story Fragment 해금·보관함·순차 재생·진행률은 정식판과 체험판에서 제거했습니다. 기존 백업의 스토리 감상 기록은 가져오지 않으며, 회로·클리어·힌트·설정은 계속 복원합니다. 자동문 완료 후에는 체험판 마무리 안내에서 후반 계산·제어·시스템 경로를 소개합니다.

XOR의 기존 두 단계 힌트를 그대로 사용하며 대기·광고·온라인 동기화를 제거했습니다. 다른 후보 문제에는 기존 힌트 데이터가 없어 문제 설명과 행동 기반 튜토리얼을 유지합니다.

체험판 HTML은 Firebase·Google 인증·광고 SDK를 포함하지 않습니다. 인증·랭킹·Lab·사용자 문제·커뮤니티 모듈도 출력물에 포함하지 않습니다. 공유 마크업에서 계정·랭킹 패널·방명록·사용자 문제 편집 영역을 빌드 시 제거합니다. 랭킹 버튼은 정식판 안내로 연결합니다. 공통 모듈의 정식판 전용 동적 import는 체험판 초기화에서 실행하지 않습니다. 회로 공유를 위해 새 서버 업로드를 추가하지 않았습니다.

정적 호스팅 요청은 필요합니다. 첫 방문부터 오프라인으로 동작하는 설치형 PWA를 보장하지 않습니다. 체험판 SW는 자기 경로 아래 자산만 처리하고 `bitwiser-demo-` 캐시만 정리합니다. 업데이트 버튼은 초안을 저장한 뒤 대기 중인 워커를 활성화하고 새로고침합니다. 기존 SW는 누락된 CSS 경로를 수정하고 삭제 범위를 `bitgame-cache-`로 한정했습니다.

체험판의 시작 스크립트·스타일에는 빌드 버전을 붙여 이전 헤더를 요구하는 캐시가 새 HTML과 섞이지 않게 합니다. 새 SW는 업데이트를 적용하기 전까지 같은 버전의 HTML과 모듈을 사용합니다. 업데이트 준비 상태는 설정 버튼의 점으로 표시하고, 설정 안의 새 버전 적용하기 버튼으로 적용합니다.

## 검증 방법과 확인 결과

2026-09-13 개편 후의 최신 결과는 [스테이지 개편 현황](STAGE_RESTRUCTURE.md)의 실행·검증 항목을 따릅니다. 아래 2026-09-05 수치는 최초 체험판의 이전 기록입니다.

```powershell
npm test
npm run build:demo
# 별도 터미널에서 npm run preview:demo 실행 후:
npm run test:demo:browser
npm run test:full:web
npm run test:full:electron
```

브라우저 검증은 개발 의존성 Playwright와 설치된 Microsoft Edge를 사용합니다. 다른 Chromium 채널은 `BROWSER_CHANNEL`로 지정합니다. `DEMO_URL`로 체험판 서버 주소를 바꿀 수 있습니다. Codex 번들 런타임을 사용할 경우 `PLAYWRIGHT_MODULE_PATH`도 지원합니다. 검증용 회로 로드는 테스트가 기존 컨트롤러의 복원 API를 호출하며, 제품에 별도 치트 API를 추가하지 않습니다.

2026-09-05 확인:

- Node 테스트 10개 통과: 기존 엔진, 모든 기준 회로·언어 대응, 별 경계, 분기·제외 단계, 오답, 기록 분리, 백업, 저장 오류, 손상·배선 검증.
- Edge 데스크톱에서 7개 문제 클리어, 다음 문제 버튼, XOR 마무리 후 재진입, 새로고침 초안 복원, 채점 중 클릭 차단과 원래 입력 복원, 기록 개선, XOR 힌트 2개, 텍스트·GIF 다운로드 확인.
- 한국어·영어에서 정식판 기능 5개 접근 차단·안내창, 4개 챕터 탐색, 제외 문제 데이터 제거, 미드나이트 네온 고정 및 기존 테마 키 보존, 수동 저장 UI 제거, 좁은 화면 안내창 확인.
- 위 핵심 흐름의 외부 서비스 요청 0건, 페이지 오류 0건, 누락 자산 0건. 외부 HTTP 요청을 차단한 상태에서 실행했습니다.
- 한국어 터치 에뮬레이션에서 입력 토글, 블록 이동, Undo/Redo, 편집 후 새로고침 자동 복원 확인.
- 클립보드 거부와 GIF 인코더 실패 시 텍스트 대안 표시·다운로드, `localStorage` 접근 자체가 차단된 상태의 시작·클리어·다음 단계 해금 확인.
- 구버전 체험판 SW에서 업데이트 버튼으로 전환 후 진행 및 무관한 다른 앱 캐시가 보존되는지 확인.
- 기존 전체 웹 시작에서 25개 스테이지, 계정 UI, Lab 노드, 페이지 오류 없음 확인. 기존 Electron은 실제 `app://bitwiser/index.html` 경로를 별도 테스트 프로필·숨김 창으로 실행해 25개 스테이지와 계정 UI를 확인했습니다. 운영 계정·저장 데이터를 사용하지 않았습니다.

Electron에서는 Google 외부 프록시의 `googleapis is not defined` 및 `Error: l` 콘솔 오류가 발생합니다. 변경 전 HEAD를 별도 폴더로 추출해 같은 방식으로 실행했을 때도 동일한 두 오류가 재현되며, 두 버전 모두 시작 버튼이 활성화됩니다. 이번 체험판 변경으로 생긴 회귀는 아니지만 정식판 Google 로그인·Drive의 Electron 호환성은 별도 확인이 필요합니다. Electron 검증 스크립트는 이 두 기존 오류를 보고서에 남기고 그 외 오류는 실패로 처리합니다.

스크린샷, 내려받은 GIF·자동 저장 검증 데이터, Electron 확인 기록은 무시되는 `test-results` 폴더에 생성됩니다. 이 결과는 사람이 처음부터 푸는 데 걸리는 시간을 검증한 것은 아닙니다.

미확인: 실제 휴대전화·Safari·Firefox, 첫 통과 15~20분 목표, 모든 정식판 온라인 기능, Electron 설치 패키지 재생성, 완전한 오프라인 실행. 운영 DB 접근 규칙·과금·OAuth 설정은 수정하지 않았으며 공개 전에 별도로 확인해야 합니다. Steam 상품 URL이 없어 가짜 링크를 넣지 않았습니다.

## 변경 위치

- `src/demo/`: 체험판 진입·진행 정책·자동 저장·검증·별·결과·공유·정식판 안내 연결.
- `src/canvas/circuitData.js`: 버전 2 스냅샷, 공통 집계, 편집기와 복원 검증이 공유하는 배선 규칙.
- `src/modules/gameUI.js`: 기존 main의 조작 버튼·설정·시스템 메뉴·테마 연동을 추출. 기존 웹과 체험판이 함께 사용.
- `src/modules/loadingScreen.js`: 정식판 로고 로딩·Start·화면 전환을 공유. 체험판은 시작 후 이야기·최근 스테이지 연결만 콜백으로 지정.
- `levels`, `grading`, `stageMap`, `hints`, `circuitShare`: 기존 동작을 기본값으로 유지하는 체험판 콜백·로컬 정책과 필요한 동적 import 분리.
- `controller`, `grid`: 복원 후 Undo 기준 상태·화면 집계 동기화, 실제 캔버스 공간에 맞춘 크기 조정.
- `storage`, `themes`, `lang.js`: 저장소 접근 예외가 앱 초기화를 중단하지 않게 처리.
- `demo.html`, `demo.css`, 이야기 JSON, 빌드·실행·검증 스크립트, 테스트 회로와 문서 추가. package에는 실질적인 테스트와 체험판 명령을 추가하고 `src/package.json`에만 ESM을 선언해 Electron의 CommonJS 실행을 유지.

조사 요약과 달랐던 점: 기존 맵은 순차형이 아닌 분기형이고 `isLevelUnlocked`는 사실상 데이터 존재만 검사했습니다. 후보 중 힌트는 XOR에만 있으며 회로 저장은 Drive JSON+GIF 업로드와 결합되어 있었습니다. 현재 작업 시작 시 저장소는 깨끗한 상태였으므로 이전 계획 단계에서 보았던 사용자 변경을 포함한 체크아웃을 그대로 기반으로 삼았습니다.
