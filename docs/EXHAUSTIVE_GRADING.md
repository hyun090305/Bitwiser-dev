# 회로 동등성 채점

채점 버전 4는 초기 상태에서의 외부 동작 동등성을 검사한다. 조합논리는 모든 입력, 일반 순차논리는 도달 가능한 `(사용자 상태, 정답 상태)`와 모든 입력을 검사한다. 대상 15개에는 버튼 해제 후 관측을, 주소 메모리(ID 38)에는 tick 없는 읽기 관측을 추가한다. 나눗셈기(ID 46)는 24개 고정 입력의 첫 COMPLETE를 1~10 tick에서 검사한다. 전파 지연이나 아날로그 글리치는 모델에 포함하지 않는다.

## 실행 의미

- 입력 변화: 메모리를 유지한 채 조합논리를 안정화한다.
- tick: 현재 입력과 메모리로 모든 D/EN을 읽고 다음 메모리를 동시에 계산한다. EN이 없거나 1이면 저장하고 0이면 유지한다.
- `compiled.createEvaluator().evaluate(state, input)`은 현재 출력과 다음 상태의 비트마스크를 반환한다. 반환 객체는 다음 호출까지 유효한 재사용 버퍼이다. 현재 상태·편집 회로를 수정하지 않는다.
- UI는 commit 이후 화면을 갱신한다. button 입력의 자동 해제도 즉시 화면에 반영한다. `lastTick`은 자동 해제 전 입력으로 관측한 tick 결과를 보관한다.
- 사용자 회로 초기 메모리는 모두 0이며 편집 중 실행 상태는 채점에 사용하지 않는다.

## 정답과 포트

조합 정답은 기존 `{ inputs, expected }[]`이다. 모든 행의 포트가 같고 0/1(또는 boolean)이어야 한다. 전체 `2^n` 입력이 정확히 한 번씩 있어야 한다. 누락·중복·상충하는 표는 검증 오류이다. 문제와 회로의 INPUT/OUTPUT 이름은 정확하게 대응하며 중복 포트는 거절한다.

순차 정답은 `{ mode: 'sequential', referenceId: 'enabled-register' }`처럼 지정한다. `src/modules/referenceFSM.js`가 언어 독립적인 정답 정의를 제공한다. 각 FSM에는 순서가 고정된 inputs/outputs, stateCount, initialState, evaluate가 있다. 배열의 i번째 포트가 비트 i다. 기존 sequence만 있는 정답에는 완전검증 통과를 부여하지 않는다. 사용자 제작 문제는 전체 진리표를 제공하는 조합 문제만 지원한다.

문제 모드가 채점 알고리즘을 선택한다. 순차 문제에서 D가 없는 제출도 상태 하나인 FSM으로 검사한다. 조합 문제의 D 사용은 금지한다.

## 컴파일과 탐색

`evaluation.js`가 연결 검증·위상 계획을 만들고 `compiledCircuit.js`가 정수 인덱스와 CSR 입력 배열로 컴파일한다. AND/OR 입력은 최대 2개로 제한하며, 첫 입력 NOT과 미연결 게이트의 기존 값을 유지한다. UI의 Map 평가와 채점의 비트마스크 평가는 같은 게이트 커널을 쓴다.

채점은 컴파일된 설계와 독립 신호 버퍼를 사용한다. 회로 전체 스냅샷을 만들지 않으며, 게이트별 객체 탐색이나 구조 서명 계산을 탐색 루프에서 수행하지 않는다. 클리어 저장용 스냅샷은 성공한 뒤에만 만든다.

FIFO 큐와 최초 발견 시 부모/입력을 저장한다. 출력 불일치 시 가장 적은 tick으로 도달하는 경로를 반환한다. 관측 경계는 정답 FSM의 `observeAt`을 따른다. 메모리 최종판은 `after_tick`, 기존 Lab과 토글 문제는 기본 `before_tick`이다. UI와 재생은 `counterexample`에서 시점을 추측하지 않고 명시적인 `trace` 사건 순서를 따른다.

25·28·29·30·32·33·34·37·38·39·40·41·42·43·45번은 기존 `after_tick` 검사를 통과한 뒤 reference에 선언된 버튼만 동시에 0으로 해제해 다시 조합 평가한다. switch는 샘플링 값을 유지하고, 전체 출력은 같은 tick의 기대값을 유지해야 한다. 제출 회로가 버튼을 switch로 바꿔도 검사 정책은 바뀌지 않는다. 사용자/reference 상태와 tick은 그대로이며 추가 평가의 임시 nextState를 큐에 넣지 않는다.

38번은 초기 상태와 각 도달 가능한 갱신 후 상태에서 WRITE=0, ADDR=0/1로 저장 공간을 각각 읽는다. D0/D1은 유지한다. 정답은 전이를 다시 실행하지 않고 현재 reference 저장 상태에서 읽는다. 각 probe는 메모리를 바꾸지 않으므로 쓰기 직후의 새 값, 서로 다른 두 저장값, 양방향 반복 읽기를 검사해도 이후 탐색을 오염시키지 않는다. 31·35·36·44번 및 legacy/Lab, 나눗셈기로 정책을 확대하지 않는다. 대상별 버튼 목록과 실패의 관측 단계, SET/EXPECT 재생 순서는 [event trace 계약](grading-event-trace.md)에 있다.

작은 상태 공간은 방문 배열, 큰 공간은 숫자 키 Set을 사용한다. product key는 `userState + refState * 2^userBits`로 표현하여 32비트 시프트 오버플로를 피한다. 정답의 상태 인코딩과 사용자 D 배치는 같을 필요가 없다.

## 결과와 한도

`status`는 `pass`, `fail`, `invalid`, `incomplete`, `cancelled` 중 하나이다. `ok: true`는 탐색이 끝났을 때만 반환한다. 실패에는 반례, 잘못된 설계/정답에는 diagnostics, 미완료에는 reason을 제공한다.

기본 한도는 사용자 D 30개, 입력 16개, 출력 30개, 발견 상태 250,000개, 출력 검사 4,000,000회(`maxTransitions`), 경과 시간 10초이다. `transitions`는 실제 상태 전이 수, `checks`는 버튼 해제·주소 읽기를 포함한 검사 수이다. 정답 전이표와 probe 입력표 크기도 같은 한도로 제한한다. 방문 배열은 기본 2^20개 이하에서 사용한다. 비트마스크 표현 한도와 실제 탐색 가능 규모는 다르다. 한도 초과는 오답도 통과도 아니며 클리어·랭킹을 갱신하지 않는다.

비동기 채점은 기본 2,048회마다 진행을 알리고 이벤트 루프로 실행권을 반환한다. 테스트별 애니메이션 대기는 없다. 상태/전이 개수만 표시하며 최종 reachable 크기를 모르는 동안 퍼센트를 표시하지 않는다. 동기 저장 재검증도 같은 탐색과 한도를 사용한다.

버튼 해제와 주소 읽기도 검사량·시간·취소 한도에 포함한다. 실제 상태 전이를 추가하지 않으며, 추가 관측 도중 끝난 `incomplete`/`cancelled`를 통과나 새 기록으로 인정하지 않는다.

## 문제 및 저장 데이터 이관

31번 변화 감지기는 이전 SIGNAL과 검출 펄스를 별도 D에 저장한다. 첫 tick에 SIGNAL=1이면 갱신 후 RISE=1이다. 메모리 최종판 1~19번은 모두 `observation: 'after'` 예시를 제공하지만 예시 자체는 채점 기준이 아니다.

`npm run stages:memory20`은 검증된 실제 보드 회로에서 최종 명세·예시·힌트·포트를 다시 생성한다. 이전 `generate-memory-stages.mjs`와 `migrate-exhaustive-grading.mjs`는 최종판 문제를 덮어쓰지 않는다.

데모 진행 및 결과에 `gradingVersion: 4`를 기록한다. 이전 결과는 새 기준으로 재검증하며 버전만 바꿔 승격하지 않는다. 새 검사에 실패한 구버전 회로도 원본 설계와 역사적 별·클리어·해금·진행을 보존하지만 현재 best/현재 버전 랭킹에는 사용하지 않는다. 한 기록의 실패로 관련 없는 정상 기록이나 전체 진행을 초기화하지 않는다. 비용 규칙과 Star 임계값은 바뀌지 않으며 구버전 랭킹 데이터를 일괄 삭제하지 않는다.

격자·포트가 달라진 회로는 이전 정의로 검증한 뒤 `legacyStageRecords`에 원본 설계를 보관하고 기존 해금과 역사적 별을 보존한다. 새 문제의 편집 회로나 현재 정답으로 자동 변환하지 않는다. 같은 보드의 데모 구기록은 기존 best/bestStars 필드에 원래 채점 버전과 함께 남고 현재 비용 기록 조회에서 제외된다. 기존 `legacyResults`도 보존한다. 정식판에서 현재 기록이라고 주장한 회로의 재검증이 실패하면 해당 기록만 `previousCostRecords`로 옮기고 역사적 클리어를 보존한다. 현재 best 결과는 계속 엄격히 검증한다.

데모 로컬 시작에서도 현재 기록의 재검증 실패/시간 초과는 해당 결과만 `previousCostRecords`에 보관하며 `historicalClear`와 기존 별·다른 진행을 유지한다. 현재 best로 다시 사용하지 않는다. 백업 가져오기는 실패하는 현재 기록을 엄격히 거절하지만, 이미 격리한 역사적 기록의 내보내기/가져오기 왕복은 허용한다.

## 검증

- `npm test`: 전체 진리표, FSM 동등성/반례, 최단 경로, 도달 불가능 상태, 상태 표현 경계, 취소/한도, 원본 불변성, UI와 채점 계산 일치, 기존 저장 이관.
- `npm run build:demo`: 최종판의 체험판 문제와 채점 모듈을 포함한다. 별 임계값은 명시적인 설정을 유지하며 자동 산출하지 않는다.
- `node scripts/verify-grading-browser.mjs`: 브라우저에서 실제 취소 버튼, 미완료·반례 표시와 잠금 해제.
- 기존 demo/memory 브라우저 검사: 클리어·별점·백업·회로 조작 흐름.
