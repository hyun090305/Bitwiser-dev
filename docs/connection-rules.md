# 회로 연결 규칙 (채점 버전 6)

[Issue #482](https://github.com/hyun090305/Bitwiser-dev/issues/482)의 연결 계약이다. 입력 수는 출발 블록 수가 아닌 도선 수로 센다.

| 블록 | 실행에 필요한 입력 | 출력 |
| --- | --- | --- |
| INPUT (switch/button) | 0 | 제한 없음 |
| OUTPUT | 1 | 금지 |
| NOT / JUNCTION | 1 | 제한 없음 |
| AND / OR | 2 | 제한 없음 |
| D | D 역할 1, 선택적 EN 역할 1 | 제한 없음 |

격자·면 점유는 그대로 적용한다. IN→OUT, 게이트/D의 fan-out, 같은 신호를 두 입력에 각각 연결하는 설계, 미사용 IN과 미사용 게이트 출력은 허용한다. 출력에 기여하지 않는 블록도 필수 입력을 만족해야 실행할 수 있다. 빈 게이트를 상수로, 한 입력 AND/OR를 buffer로 사용하지 않는다.

## 편집과 실행의 경계

`connections.js`의 `validateConnections`가 방향·입력 수·D 역할·조합 순환을 검사한다. 편집은 `complete: false`로 입력 부족을 허용한다. `canEditConnections`는 이전 위반의 유지/감소를 허용하므로 기존 회로를 한 도선씩 고칠 수 있다. 새 위반이나 입력 초과 증가, 손상된 역할에 새 잘못된 도선을 더하는 작업은 거부한다.

배선 확정, 블록 교체, 연결을 유지한 이동, 영역 이동, 붙여넣기는 최종 블록/도선을 검사한다. 붙여넣기의 IN/OUT→JUNCTION 변환과 기존 connector 병합 후에도 같은 검사를 적용한다. `hasValidWireLayout`은 최종 경로들의 상호 점유까지 확인한다. 거부/취소한 이동은 원본과 실행 상태를 복원하고 이력에 추가하지 않는다. Escape와 touchcancel도 진행 중인 편집을 취소한다.

실행·동기/비동기 채점은 `prepareCircuit`/`compileCircuit`의 완전성 검사를 통과해야 한다. 조합·순차·memory20·Lab에 같은 기본 규칙을 적용한다. 실패하면 신호를 `?`로 표시하고 프레임 상단 우측의 `⚠ 미완성 · 개수` / `⚠ Incomplete · count` 배지로 안내한다. 다른 연결 위반은 `연결 오류` / `Invalid circuit`로 구분한다. hover·키보드 포커스·클릭/탭으로 블록/도선과 원인을 담은 팝오버를 연다. 채점은 `invalid`이며 정답 불일치 반례를 만들지 않는다. 반복 평가로 경고 창을 띄우지 않는다. 실패 tick은 메모리·tick·button 상태를 바꾸지 않으며 수리 후 다시 실행할 수 있다.

거부된 조작은 현재 회로의 실행 오류와 별개인 `⚠ 편집 거부` / `⚠ Edit rejected` 토스트로 프레임 상단 중앙에 약 3초 표시한다. 방향·입력 상한·역할·순환의 구체적인 원인은 공통 연결 검사에서 가져오며 교체·붙여넣기의 최종 후보에도 적용한다. 공간 충돌도 안내한다. 일반 클릭·마우스 이동·같은 모드 키 반복·다음 편집·취소·Undo/Redo·복원으로 지우지 않는다. 새 거부 사유는 내용을 교체하고 3초를 다시 센다. 안내 자체는 실행 가능 여부나 설계·Q·tick·버튼·비용·팔레트·이력을 바꾸지 않는다.

안내가 없어도 상단 영역 높이는 유지한다. 배지·토스트는 회로 칸 바깥에 있고, 상세창은 보드 배치를 밀지 않는다. 좁은 화면에서는 같은 고정 영역 안에서 배지와 토스트를 두 줄로 나눈다. 모두 남색 배경·경고 테두리·밝은 글자와 아이콘을 사용한다.

## 문제 유형과 자동 재생

스테이지의 `levelAnswers[id].mode === 'sequential'`이 tick 바를 결정한다. D/button이 없거나 마지막 부품을 삭제해도 tick 문제는 바 공간을 유지하며, 빈 회로/미완성 회로는 실행을 차단한다. 조합논리 문제와 커스텀 진리표 문제에는 tick 바나 자동 tick을 추가하지 않는다. Lab은 명시적으로 순차 실행 모드를 사용한다.

tick 문제의 초기화·복원과 소개 화면이 끝나고 회로가 실행 가능하면 기본 자동 재생한다. 이는 정답/클리어 여부와 무관하다. 편집 중에는 잠시 멈추며, 성공·거부·취소 후 실행 가능하면 다시 타이머를 예약한다. 재개 자체는 즉시 tick하거나 상태를 초기화하지 않는다. 사용자가 직접 누른 일시정지는 같은 문제의 편집·복원 후에도 유지하며, **계속**을 눌러 해제한다. 새 문제에 진입하면 기본 자동 재생 의도로 시작한다.

INPUT switch/button의 클릭·탭·길게 누르기는 입력 신호 조작이다. 실제 다른 칸으로 이동하기 전의 드래그 후보는 편집 정지 사유로 보지 않는다. 0/1 전환만으로 재생 버튼·tick 수·타이머 주기를 초기화하지 않으며, 수동 정지 중에도 그 선택을 유지한다.

채점·결과 화면·비활성/백그라운드·소개 화면에서는 실행하지 않는다. 결과 재생은 기존 trace와 실행 상태 복원을 유지하며 이 차단이 풀린 뒤에만 자동 재개한다. 실행 정책은 `playbackPolicy.js`, 표시와 화면 차단은 `memoryControls.js`가 담당한다. 표시·프레임 갱신은 tick을 직접 수행하지 않는다.

## D 자기 피드백

현재 Q→자신의 D, 현재 Q→자신의 EN을 허용한다. 후자는 별도의 D 역할 입력이 필요하다. 자기 EN으로 Q=0을 유지하는 회로도 구조적으로 유효하다. D 외 직접 자기 연결과 D를 통과하지 않는 모든 방향성 순환은 금지한다.

자기 도선의 첫/마지막 좌표만 같은 D 칸일 수 있다. 경로는 직교 한 칸씩 이동하며 다른 면으로 복귀한다. 중간의 좌표 반복, 같은 면 재사용, 다른 블록/도선 관통은 허용하지 않는다. 최소 닫힌 경로는 D 칸과 서로 다른 중간 세 칸으로 이루어진다. 이동·복사·삭제·Undo/Redo에서도 도선 하나와 양 끝점을 함께 취급한다. 비용은 중간 칸만 세며 D 끝점을 중복 과금하지 않는다.

첫 입력은 D, 추가 입력은 EN이다. 두 유효 입력의 역할 교환은 기존 클릭/탭을 사용한다. 실제 삭제의 영향을 받은 D에 한 입력만 남으면 D로 정규화한다. 불러오기·평가·무관한 편집은 손상된 역할을 수정하지 않는다. 모든 D는 이전 Q로 동시에 다음 상태를 계산하며 초기 Q=0, button 1tick, 관측 시점, divider COMPLETE 계약은 유지한다.

## 저장과 성과

v2 읽기/v3 설계 저장을 유지한다. `savedCircuitRecord.js`와 `stageCircuit.js`는 형식·참조·공간/스테이지 제약을 검증하고 논리적 미완성/과거 위반은 보존한다. 손상된 참조나 공간 경로를 정상 설계로 받아들이지는 않는다. 자기 피드백 도선과 D/EN은 Electron 파일·체험판 draft/백업·공통 복원 경로를 왕복한다. Undo/Redo로 복원한 위반도 실행만 차단하고 편집할 수 있다.

`GRADING_VERSION`은 5→6, 가격은 `cost-v1`을 유지한다. 스테이지 규칙/랭킹 키는 채점 버전을 포함한다. 과거 클리어·획득 별·해금·설계·기록을 보존하며 이전 기록을 현재 비용 기록으로 승격하지 않는다. 새 기록 생성과 랭킹 제출/조회는 새 채점을 다시 통과해야 한다. 단계 하나의 잘못된 현재 기록은 격리하고 다른 진행은 보존한다.

## 검증과 영향 범위

- `npm test`: 블록별 입력 수, 실행/동기·비동기 채점, 방향/순환, 단계적 수리, tick 원자성, v2/v3, 역할 보존, 비용/과거 성과 검사.
- `npm run build:demo` 후 `npm run test:connections:browser`: 정식 모듈과 빌드된 체험판 모듈의 실제 컨트롤러에서 한영 자기 연결 그리기, 역할, 이동/영역 이동, 복사/붙여넣기, 삭제, Undo/Redo, 충돌/취소, 교체와 connector 병합을 검사한다. 전용 harness이며 실제 진입점 검사는 별도로 수행한다.
- `node scripts/verify-playback-status.mjs` / `node scripts/verify-playback-status.mjs --electron`: 실제 정식 웹·빌드된 데모·별도 프로필 Electron에서 한영/넓고 좁은 화면의 보드·바 좌표와 크기, 배지/팝오버/토스트, 3초 유지/갱신, 문제 유형, 기본 재생/수동 정지, 편집/채점/화면 차단을 검사한다.
- `npm run test:full:web`, `npm run test:demo:browser`, `npm run test:saves:electron`: 실제 게임 캔버스에서 자기 D/EN을 그리고 Undo/Redo한다. 체험판은 백업 UI로 복원하고, Electron은 별도 프로필/외부 요청 차단 상태에서 저장·프로세스 재시작·복원·tick을 검사한다.
- 기존 실행 경로 회귀 명령과 preview 전제는 [개발 흐름](development-workflow.md)의 검증 표를 따른다.

`tests/fixtures/demo`, `stages`, `memory20`의 81개 예제(31개 stage ID)를 새 공통 검사·배치 검사·한영 채점·비용 계산으로 재검증한다. 예제 파일과 가격/별 기준은 변경하지 않는다. 파일명의 `-3`은 현행 3별이나 전역 최적해의 증명이 아니다. 실제 운영 플레이어의 최고 기록은 이 검사의 대상이 아니며, 접근하지 않은 기록의 무영향을 주장하지 않는다. 실행 결과와 환경 제한은 PR에 기록한다.
